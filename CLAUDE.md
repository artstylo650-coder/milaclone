# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm start                     # run the app (default http://localhost:4321)
docker compose up -d --build  # run in Docker on 127.0.0.1:8182
PORT=8080 node server.js      # run on a different port
npm test                      # backend tests: API + ComfyUI bridge (node --test, no framework)
node --test test/api.test.js  # run a single test file
npm run test:e2e              # Playwright end-to-end tests
npx playwright test e2e/ui.spec.js -g "creates a note"  # single e2e test
npx playwright install        # one-time: fetch browser binaries for Playwright
npm run explore -- --steps 300 --seed 42  # random-action robot; report in qa-report/explore/
```

`scripts/explore.js` starts its own server on `.explore-data/` (port 4331), seeds a board, performs seeded random user actions in Chromium and after each one checks for JS/HTTP errors, screen-vs-database drift, broken references (lines, groups, columns) and native text selection. A finding can be replayed with the same `--seed`.

Both test suites are self-isolating: `test/api.test.js` points `DATA_DIR` at a fresh `mkdtemp` before requiring `db.js`; `playwright.config.js` starts its own server on port 4322 with `DATA_DIR=.e2e-data` (wiped each run). Neither touches real board data — but note that `db.js` opens the SQLite handle on `require`, so any code that requires it must set `DATA_DIR` first if isolation matters.

## Architecture

Express + SQLite backend split into small CommonJS modules, vanilla ES-module frontend, no build step.

Backend modules live in `backend/` next to `routes.js`/`db.js`: `version.js` (package.json version + git commit), `update.js` (check/apply updates from git: snapshot, `pull --ff-only`, `npm install` only if the manifest changed, restart via exit code 75; routes are loopback-only), `migrate.js` (numbered DB migrations, `schemaVersion` in `meta`, `VACUUM INTO` snapshot before any beyond the baseline), `transfer.js` (copy/move of a selection), `history.js` (undo journal), `events.js` (SSE live updates), `trash.js` (soft-delete store), `backup.js` (snapshots, export/restore archives), `comfy.js` (ComfyUI / RunPod bridge), `translate.js` (PT ⇄ EN note translation through the free MyMemory API — no AI, no key; one request per line, then tags/weights/comma spacing repaired from the original). Each creates its own tables on `require`, after `db.js`.

**Backend flow** (`server.js` → `backend/routes.js` → `backend/db.js`):
- `db.js` opens `better-sqlite3` in WAL mode on import, creates schema on first run, and seeds a root `Home` canvas. It exports prepared statements (`stmt.*`) and helpers; **routes call the prepared statements directly** rather than going through a repository layer.
- Schema: `canvases` (self-referential tree via `parentCanvasId`), `items` (belong to a `canvasId`, may nest under `parentItemId` for cards inside a column), `meta` (key/value; stores `rootCanvasId`).
- `items.data` is a JSON string in SQLite but always an object at the API boundary — `rowToItem` parses on read, routes `JSON.stringify` on write.

**The board/canvas duality is the trickiest invariant.** A `board`-type item on canvas A owns a freshly-created child canvas B (see `routes.js` POST `/api/item`). The card's title, color, and icon live on the child canvas row, not the item — GET `/api/canvas/:id` augments board items with `_childTitle`/`_childCount`/`_childColor`/`_childIcon`, and PATCH writes title/color/icon *through* to the child canvas and strips them off `item.data`. Deleting a board triggers `deleteItemDeep` in `db.js`, which recursively collects descendant canvases and wipes the entire subtree in one transaction.

**Groups and transfers.** A `group` item is a Comfy-style frame: members point at it through `data.groupId` (the frame stores its own id there too) and membership follows geometry — dropping a card inside a frame joins it, dragging it out leaves. Clicking a card selects only that card; clicking a frame's title selects the frame plus its members. Deleting a frame frees its members (`deleteItemDeep`) instead of deleting them. Copy/cut/paste/duplicate all go through `POST /api/transfer` (`transfer.js`): one transaction that either deep-copies the selection (column cards, group members, nested board canvases remapped to new ids) or, for cut, moves the originals — cut never deletes anything.

**Undo/redo is journaled in SQLite.** `history.js` installs triggers on `items` and `canvases` that copy every row change into `history_changes` while a step is open. A middleware at the top of `routes.js` opens one step around each mutating `/api` request, so **mutating handlers must stay synchronous** (writes after an `await` would escape the journal). Steps are per browser tab (`X-Client-Id`, from sessionStorage); requests with the same `X-Undo-Key` within 5 s merge into one step — the client sets it with `startAction()` in `api.js` for multi-request actions (group, delete selection, import) and `edit:<id>` for debounced text saves. Undo/redo just replays row images and the client reloads the affected canvas (`public/js/board/history.js`). Ctrl+Z inside a text field stays the browser's own text undo.

**Lines, trash, live updates.** A `line` item connects two cards (`data.from`/`data.to`, optional `label`, `arrow`, `dashed`); it has no DOM card — `connections.js` draws it in the SVG layer from the cards' layout boxes. `deleteItemDeep` removes lines touching a deleted card, collects every removed row, and `DELETE /api/item/:id` hands them to `trash.js` (group frames and lone lines are not trashed). After each journaled request the middleware publishes the touched canvas ids on `/api/events`; other tabs call `reloadView()` in `main.js`, which defers while the user is typing or dragging.

**ComfyUI bridge.** A `comfy` card stores `workflowId`, `prompt`, `negative`, `runs`, `slots` (LoadImage node id → source card id or `'blank'`), `params` (`nodeId.input` → value for the fields the user exposed; the exposed list lives on the workflow row), `seedMode`/`seed`. Cards connected to it by lines are its inputs: photos and groups/columns fill the LoadImage slots (a group is a *set*: one job per photo, several sets are paired by position and must match in size), notes are the prompt (English twin preferred). `comfy.js` `plan()` resolves all that without running (the card calls `/api/comfy/plan/:id` to show "Gerar N" and per-slot thumbnails; `run()` uses the same plan), fills the API-format workflow (positive/negative text found by following sampler conditioning links, seeds per `seedMode`, `params` overrides), queues one job per photo of the set and variation on local ComfyUI or a RunPod worker-comfyui 5.x endpoint, polls, and places results as image cards in a group under the source (`data.comfyAnchor`, each image keeps `comfyFrom`); later batches stack below. Placement is collision-aware (`resultGroup`): the frame reserves its final size (`reservedSize`), then tries under the source, then to its right, then under every card on the board with a dashed `line` back to the source; card heights are estimates (`boxOf`). `/api/comfy/cancel/:id` stops the latest batch. Card layout (`comfynode.js` `draw()`): the card IS its image — a title row (editable name, shortcuts: enhance results, download, ⋯ menu) and `.comfy-frame` showing the newest result (`latestImage()`: last image of the node's last result frame; placeholder before the first). Selecting the card shows `.comfy-bar` under it (CSS `.item.comfy.selected`): prompt, chips (Proporção from an exposed width+height pair or aspect-ratio list via `ratioSpec()`, Qualidade → `testScale`, Imagens por foto → `runs`, Seed → `seedMode`/`seed`/`seedBatch`), a Mais ajustes button and the round send button (`Gerar N`). Chips open `openPop()` popovers under the bar; **Mais ajustes** opens a panel (`buildAdjust()`: workflow, per-slot inputs, negative prompt, exposed fields incl. the folded `sizeRow()`/`aspectRow()` pickers). The card follows the workflow's `kind` (`kindOf()` in `comfy.js`, from `analyze()`): `generate` (no image input), `edit` (images + prompt: the bar adds an input-summary row, a compare button holds the original over the result via `comfyFrom`, and before the first result the faded original shows), `upscale` (images, no prompt: no prompt box, variations, seed chip or quality chip; the lead chip is the resolution/scale field found by `upscalePrimary()` and the send button says Aprimorar; seed stays in Mais ajustes). While jobs run `paintStatus()` covers the image with a ring + count + Stop and the frame glows. Popover/section open state is view state, never board data. Waiting is liveness-based: `local.poll` treats a prompt still in ComfyUI's `/queue` (or with a history entry) as alive and only fails it as lost after 5 polls where ComfyUI knows nothing of it; `COMFY_JOB_TIMEOUT_MS` (default 24 h) is just a cap. Failures that are not real job errors are `recoverable` (`/api/comfy/recover/:id`, and on boot `resume()` re-checks failures from the last 24 h). `startLocal()` launches the configured start file (`localLaunch`, accepted only from loopback requests without `x-forwarded-for`) when `dispatch()` finds a local ComfyUI down. `testScale` on the card (and `testScale` in the enhancer settings) multiplies the workflow's size fields (`scalable`, defaulting to width/height/resolution/megapixels-like names) so trials run small. Progress: while jobs are watched, a websocket to local ComfyUI feeds `stepProgress`; `status()` returns `fraction`/`step`/`indeterminate` (RunPod has no steps). Workflows ending in PreviewImage return their temp images. The **enhancer** (`enhance()`, settings in `meta` `comfy.enhance`) sends image items through one chosen single-image workflow: jobs have `kind='enhance'`, `itemId`=anchor (the common group or the first image), results are framed under the anchor, the original gets `data.enhanced` and results `data.enhancedFrom`. Jobs live in `comfy_jobs` and resume on boot. Settings sit in `meta` under `comfy.settings`; env vars override them and the RunPod key is never sent to the browser. `test/fake-comfy.js` stands in for both services in tests; the comfy e2e file is serial because the settings are global to the app server.

**Frontend** (ES modules under `public/js/`, entry `main.js`; folders: `core/` state/api/util/markdown, `board/` canvas behaviour, `ui/` menus/panels/theme/export, `features/` ComfyUI + Quick notes — `docs/ARQUIVOS.md` maps every file in Portuguese). The UI text is Brazilian Portuguese, written directly in the code (no i18n layer); e2e selectors use those strings. Colors come only from CSS variables in `style.css`; `ui/theme.js` switches `data-theme` (light/dark/sepia/graphite/auto) and `data-font` (four self-hosted pairs from `@fontsource-variable`, served at `/vendor/fonts`):
- `state.js` is the shared mutable app state. Because ES module bindings can't be reassigned by importers, anything that mutates at runtime (`view`, `cam`, `selectedId`, `drag`, …) lives as a field on the exported `state` object; collections mutated in place (`elMap`) are exported directly.
- `main.js` is the entry point: boots, wires global keyboard/pointer handlers, and owns `openCanvas(id)` — the single navigation primitive that fetches, resets selection, and updates `location.hash`.
- `cards.js` owns all DOM rendering for items. `render()` clears `#world` and re-renders everything; `refreshItem(it)` swaps a single card. Cards inside a column render as children of the column's DOM, not directly under `#world`.
- `drag.js` handles drag-in/drag-out of columns: dragging a card out of a column reparents it to `#world` mid-drag and clears `in-column`; dropping onto a `.col-body` reparents and reorders siblings via `api.patchMany`.
- `quicknotes.js` owns the mobile-only **Quick notes** workspace (`#quicknotes`, shown by the footer's "Quick notes" tab): a three-level stack (overview → list detail → task detail) plus a modal search layer, all styled from its own token set in `style.css`. Every `todo` card anywhere in the tree is a list there — `GET /api/todos` returns them all and writes go back through `PATCH /api/item`, so the same card is edited from both surfaces. Tasks carry extra fields the canvas ignores (`starred`, `due`, `tags`, `note`, `noteStyle`) and blank-text tasks (the canvas editor's placeholder rows) are never listed. Screens are static markup in `index.html` and this module fills the `[id]` regions, so fields holding a caret survive a re-render; while it's open `main.js` hands over the keyboard and pointer via `isQuickNotesOpen()`.
- Other modules: `viewport.js` (pan/zoom + `screenToWorld`), `tools.js` (toolbar arming), `editing.js` (select/edit/save), `menus.js` (color palette + context menu), `clipboard.js` (copy/cut/paste via `/api/transfer`; the system clipboard carries a `milaclone-clipboard:` marker so the last copy wins between board cards and external text/images), `groups.js` (frame hit-testing), `connections.js` (SVG layer: lines between cards, link-handle drag, node port wiring — the generic node tool is not on the rail), `create.js`, `mobile.js` (mobile header/footer chrome), `api.js` (`fetch` wrappers; adds `X-Client-Id`/`X-Undo-Key`), `history.js` (undo/redo buttons and keys), `panel.js` (modal panels + confirm), `appmenu.js` (top-bar "⋯" menu, trash panel, backup), `cmdk.js` (Ctrl+K search/commands and double-click quick add), `lightbox.js` (full-size image viewer), `comfynode.js` (ComfyUI card + settings), `enhance.js` (enhance icon/menu/selection bar → `/api/comfy/enhance`, floating progress, options dialog), `translate.js` (translated twin notes joined by a dashed line; re-translates when either note's edit ends, via `onEditEnd` in `editing.js`), `markdown.js` (safe Markdown subset for note bodies), `arrange.js` (align/distribute/tidy, arrow nudge, snap to grid), `minimap.js`, `tags.js` (card tags + board filter), `export.js` (PNG/PDF via `html-to-image` and `jspdf`, served from `node_modules` at `/vendor/*`).
- Modals that own the keyboard (`isPanelOpen`, `isLightboxOpen`, `isCommandOpen`, `isQuickNotesOpen`) are checked at the top of `main.js`'s keydown handler.
- Board cards can be resized (w and h; a resized board lets its cover photo fill the space). Per-card tools only show for a single selection.
- Lucide icons come from a CDN `<script>` and are refreshed after DOM changes via `refreshIcons()`; the helper no-ops if the CDN failed to load.

**Auto-save model:** every user edit fires a PATCH — there is no explicit save. The model is single-document, last-write-wins; other clients refresh through `/api/events` but there is no merge of concurrent edits.

## Data & config

- `data/board.db` (+ `-wal`, `-shm`) — all board content. Delete to reset.
- `public/uploads/` — user-uploaded files and ComfyUI results (25 MB upload cap, mime-filtered in `routes.js`); `UPLOAD_DIR` overrides it and `server.js` serves it at `/uploads`. `uploads/thumbs/` is a disposable WebP cache.
- `DATA_DIR/backups/` (or `BACKUP_DIR`) — daily `board-*-auto.db` snapshots (14 kept) plus `before-restore`/`manual` ones.
- Env vars: `PORT` (4321), `HOST` (0.0.0.0), `DATA_DIR` (`./data`), `UPLOAD_DIR`, `BACKUP_DIR`, `BACKUP_INTERVAL_HOURS` (24), `BACKUP_KEEP` (14), `TRASH_DAYS` (30), `COMFYUI_URL`, `RUNPOD_ENDPOINT_ID`, `RUNPOD_API_KEY`, `RUNPOD_API_BASE` (tests), `COMFY_POLL_MS`, `COMFY_JOB_TIMEOUT_MS`, `TRANSLATE_API` (MyMemory-compatible server; tests point it at `test/fake-translator.js`).
- Windows app: `Instalar Milaclone.bat` → `scripts/windows/instalar.ps1` registers a logon scheduled task that runs `iniciar-oculto.vbs` → `servidor.ps1` (keep-alive loop with a mutex; restarts at once on exit code 75, after 3 s otherwise) and makes `--app` shortcuts; `desinstalar.ps1` undoes it. The `.ps1` files carry a UTF-8 BOM on purpose (Windows PowerShell 5.1 misreads accents without it). PWA: `public/manifest.webmanifest`, `public/sw.js` (does nothing but make it installable), icons generated by `scripts/make-icons.js`. `UPDATE_REPO_DIR` points version/update at another checkout (tests; e2e uses a non-git temp dir so nothing reaches the network).
- Docker: `Dockerfile` is a two-stage alpine build (stage 1 installs build deps so `better-sqlite3` compiles against musl; stage 2 copies `node_modules` in). `docker-compose.yml` mirrors the sibling `reflections` deployment on `xbox` — loopback-only port, resource caps, named volumes `milaclone_data` (`/data`) and `milaclone_uploads` (`/app/public/uploads`), fronted by Tailscale Serve.
